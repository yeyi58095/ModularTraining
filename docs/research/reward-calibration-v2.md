# Reward v2：單位修正與分數尺度校準

2026-10-15，供 progressive_v2 從頭訓練前審視。候選版本為 `spatial_reward_v2_candidate_1`，目前只在離線重計分工具中實作，未部署正式 SLX。這份校準區分三件事：公式是否符合定義、固定飛行資料在新公式下的分數、使用新 reward 訓練後的行為。前兩者可以先測，不能據此宣稱第三者成立。

## 可重現的候選定義

先只修正兩條支路，其餘八項完整保留，以減少同時改變的因素。`d` 為 guidance 輸出的非負距離，單位公尺；目前幾何是引導路徑的局部直線橫向距離，不是到使用者原始有限折線的最近距離。原始路線距離必須另行評估。

```text
cross_track_new = 0.2 - w * d / 30
distance_bonus_new = 0.1 + 0.05 * max(0, 1 - d / 10)
reward_new = reward_old - cross_track_old - distance_bonus_old
             + cross_track_new + distance_bonus_new
```

參考候選 `w=0.2` 沿用原本直線條件下的距離懲罰斜率；額外測試 `w=0.4,0.6` 作敏感度比較，不因分數較高就選較弱懲罰。`30m` 是保留的尺度，不是成功門檻；`10m` 是原先加分條件的物理單位解讀，也不是已確認的任務容許誤差。

- 移除 cross_track 的曲率減半分支，讓同一距離在直線與轉彎受到相同的直接懲罰；這是明確的候選設計決定，不聲稱已還原原作者意圖。
- 移除到局部 waypoint 距離在 30～150m 的額外加分。
- 原本近乎固定的「正規化 d≤10」加分改為物理距離 0～10m 內連續遞減，10m 處沒有跳變。
- 保留此支路每步 0.1 的基底；不是刪去整條 distance_bonus。
- 原本獨立的 curvature_distance 項仍保留；並非刪除所有曲率相關 reward。朝向、角速度、轉向追蹤、距離變化、動作超限與變化扣分均未改。
- 不變更 observation、guidance、reward 以外的接線、IsDone、PPO 或探索設定。

只看被修改的兩項，其他因素固定：

| d（m） | w=0.2 | w=0.4 | w=0.6 |
| ---: | ---: | ---: | ---: |
| 0 | 0.3500 | 0.3500 | 0.3500 |
| 5 | 0.2917 | 0.2583 | 0.2250 |
| 10 | 0.2333 | 0.1667 | 0.1000 |
| 20 | 0.1667 | 0.0333 | −0.1000 |
| 30 | 0.1000 | −0.1000 | −0.3000 |
| 50 | −0.0333 | −0.3667 | −0.7000 |

距離越大，這兩項的合計必定下降。但實際飛行中其他項也會變化，不能將這張表當作整體策略不會鑽漏洞的證明。

來源為 Agent31600、正式空間循跡模型 SHA256 `495afb97a9fa463b4500d168909ea28f649a12912f12c0631ec1e85b93c1b6be`。原評估資料夾 `diagnostic_packages/stage6_review/main/reports/evaluation_20261014_090252_tpa0964215`，兩個完整風場情境各 3000 transitions。

| seed | 原 reward | w=0.2 | w=0.4 | w=0.6 | guidance d RMS（m） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 202 | 2841.37 | 2710.01 | 2558.42 | 2406.84 | 8.58 |

表格為四捨五入的摘要，以產生的 calibration.json 精確值為準。同一條 trace 的動作與飛行時間完全相同，分數變化只是重新計分，不是政策改善或退步。w=0.2 下，cross_track 分別少約 27.08／36.84；distance_bonus 少約 104.28／120.09；動作變化扣分仍為 −38.9／−38.5。

這兩條資料只能支持「單位修正會明顯改變分數尺度」。它們不能選出最佳懲罰強度，也不能證明 2666 就應該通過、或原本 2700 應平移成某個固定數字。

## 課程門檻狀態

progressive_v2 原草案中的 reward 1200／1800／2000／2200 尚未正式校準；尤其所有有風階段使用 2200 的理由不足。不得把這些數字當作本次候選的已驗證門檻，也不把原 reward 分數與新分數接成同一條曲線。

本次先保留 JSON 作為未部署的課程草案，遠端配方仍是 start=false。離線工具不自動改寫 JSON。單一既有 agent 的關閉探索評估，不能代表新 agent 訓練時的 reward 分布；目前也沒有完整的八階段成功／失敗樣本和使用者確認的實際距離品質標準，因此不能誠實產生八個「正式校準值」。

後續若使用此候選開始新的短訓練驗證，應記錄 reward 版本、候選參數及環境 SHA，先看各項分布與實際距離品質，再決定是否部署及如何訂訓練門檻。課程的跑滿比例與獨立距離評估仍需並用。新公式仍有正向基底、距離變化與轉向項，不能宣稱已完全消除偏好存活時間或其他投機行為。

## 重現方式

```matlab
addpath('tests');
test_spatial_reward_candidate();
test_reward_breakdown();
report = calibrate_training_rewards( ...
    "diagnostic_packages/stage6_review/main/reports/evaluation_20261014_090252_tpa0964215", ...
    "tests/output/my_reward_calibration");
```

輸出目錄必須不存在，工具不覆寫舊結果。驗證原始逐步 reward 加總、t 與 t+0.1 秒對齊、距離正規化、環境 SHA 及 evaluation 總分後，才重計分；報告保存來源 evaluation／MAT 的 SHA256、checkpoint 來源、候選參數、逐項差值、全程及10秒後距離統計。檔案寫到新的 output，來源 traces、checkpoint、課程與正式 runtime 不改。

候選純函式在 `+checkpointreview/spatial_reward_candidate.m`。合成測試涵蓋 0/5/10/30/50m、10m 邊界連續性、單調性、控制扣分保留及不合法輸入。它是離線公式，不會因新增檔案就改變 retry 的 reward。
